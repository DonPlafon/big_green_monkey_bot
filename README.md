# big green monkey

[русский](README.md) · [english](README.en.md) · [бот-пример](https://t.me/big_green_monkey_bot)

**ru:** бот для приёма участников в группы и каналы Telegram: заявки, капча, отдельные настройки чатов и управление через Mini App. Работает на Telegram Serverless без собственного сервера.

**en:** a Telegram admission bot with join requests, captcha, per-chat settings and a Mini App dashboard. Runs on Telegram Serverless without a separate server.

**Попробовать:** [@big_green_monkey_bot](https://t.me/big_green_monkey_bot) → `/start` → «управление».

## Что умеет

- Управлять несколькими группами и каналами с независимыми настройками.
- Принимать новые заявки сразу или после капчи в личных сообщениях.
- Проверять новичков в супергруппе: ограничивать сообщения до ответа на капчу.
- Подключать чат через нативное окно Telegram с выдачей боту нужных прав.
- Показывать ожидающих участников, статистику за всё время и журнал с фильтрами.
- Давать администратору возможность вручную пропустить участника и поставить чат на паузу.
- Работать через Mini App и обычные инлайн-кнопки бота с общей базой настроек.
- Убирать группы и каналы из личного списка, даже если бот удалён или администратор потерял доступ.

Интерфейс на русском: короткие тексты в нижнем регистре, чёрный фон, скруглённые карточки без рамок. Капча — эмодзи или простой пример, с 1, 3 или 5 попытками.

## Режимы входа

| Режим | Где работает | Что происходит |
| --- | --- | --- |
| приём заявок | группы и каналы | бот сразу одобряет новую заявку |
| капча в личке | группы и каналы | бот отправляет задание заявителю и одобряет заявку после правильного ответа |
| капча в группе | супергруппы | новичок входит, получает ограничение на сообщения и задание на инлайн-кнопках |

Для одного чата выбирается один режим. В режиме капчи в группе бот сам не одобряет заявки: участник входит по обычной ссылке либо его принимает администратор. В каналах проверка доступна **перед принятием**, через личные сообщения.

Если попытки закончились, можно выдать новую капчу, оставить заявку администратору или отклонить её. Для капчи внутри группы доступны новая проверка или удаление участника с возможностью зайти снова.

## Как запустить своего бота

### 1. Подготовить Telegram

Нужны **Node.js 24+**, npm, Git и доступ к **Telegram Serverless** у вашего бота.

1. Создайте отдельного бота в [@BotFather](https://t.me/BotFather).
2. В настройках бота откройте **Serverless → CLI Access → Access token**.
3. Сохраните токен для следующего шага. Это токен вида `app<id>:<secret>`, отдельный от обычного Bot API token.

Начните с пустого Serverless-проекта: публикация синхронизирует модули целиком. Если в выбранном боте уже работает другой проект, сначала сохраните его исходники.

### 2. Скачать исходники

```sh
git clone https://github.com/DonPlafon/big_green_monkey_bot.git
cd big_green_monkey_bot
npm ci
cp .env.example .env
```

Откройте `.env` и замените имя бота на своё, **без `@`**:

```dotenv
VITE_BOT_USERNAME=your_bot_username
```

Это публичное имя для ссылки «открыть в telegram». Токен сюда вставлять не нужно. В PowerShell вместо `cp` можно использовать `Copy-Item .env.example .env`.

### 3. Подключить и опубликовать

```sh
npx tgcloud init
npx tgcloud login
npm run deploy
npm run setup:bot
```

При `login` вставьте **CLI Access token** своего бота в скрытый запрос терминала.

- `init` создаёт локальное состояние CLI, не перезаписывая существующие исходники.
- `deploy` запускает серверные тесты, собирает Mini App, применяет безопасные изменения схемы, публикует проект и синхронизирует webhook.
- `setup:bot` проверяет облачные модули и базу, задаёт команды, описания профиля и кнопку «управление».

CLI выведет адрес Mini App: `https://app<BOT_ID>.tgcloud.ai/`. Отдельный VPS, домен, база данных и запуск процесса бота не требуются. Main Mini App в BotFather можно настроить дополнительно; для запуска через кнопку меню это не обязательно.

Авторизация CLI хранится в игнорируемом `.tgcloud/`. Новый экземпляр использует собственную базу Telegram Serverless; данные бота-примера в репозиторий не входят.

### 4. Подключить группу или канал

1. Откройте своего бота и отправьте `/start`.
2. Нажмите «управление» → «добавить чат».
3. Выберите группу или канал в нативном окне Telegram и подтвердите права бота.
4. Выберите режим и включите бота. Новые чаты подключаются на паузе.
5. Для режима с заявками создайте в настройках **ссылку с заявкой** и используйте её для новых участников.

Нативный выбор внутри Mini App требует Telegram Mini Apps API **9.6+**. В старом клиенте используйте `/start` → «добавить чат или канал»: появится обычная клавиатура выбора.

Для первичного подключения нужны права назначить бота администратором. Дальнейшее управление доступно владельцу или администратору с правом приглашать участников; для групп также требуется право ограничивать участников. Доступ перепроверяется через Telegram при каждом действии, включая чтение данных в Mini App.

## Настройки и поведение

- У каждого чата свои режим, пауза, тип капчи, число попыток и действие после ошибок.
- Кнопки капчи принимает только тот участник, которому выдана проверка.
- Пауза останавливает новые проверки. Уже выданные капчи и ограничения сохраняются до ответа, выхода или решения администратора.
- Попытки и действие после ошибок фиксируются при создании проверки; изменение настроек применяется к новым участникам.
- Для капчи по заявке бот пытается написать в разрешённое Telegram пятиминутное окно контакта. Если сообщение не доставлено, заявка остаётся ждать администратора, а ошибка появляется в журнале. У отправленной капчи нет пятиминутного срока решения.
- Ограничения, изменённые другим администратором, бот не снимает автоматически при решении капчи.

## Убрать чат из списка

Откройте чат в Mini App или инлайн-меню → **«убрать из списка»** → **«убрать»**. Если доступа уже нет, остаётся только карточка с названием и типом чата, повторной проверкой доступа и удалением из списка. Настройки, участники, журнал и статистика недоступны без актуальных прав.

Удаляется только связь чата с вашим аккаунтом: списки других администраторов, настройки и уже выданные капчи сохраняются. **Это не останавливает работающего бота** — для остановки новых проверок сначала поставьте чат на паузу. Повторное подключение через выбор чата вернёт его с прежними настройками.

## Ограничения

- **Задержки приёма, таймеры удаления и рассылки не реализованы.** Планировщик и фоновые задачи не используются.
- Капча — простая проверка взаимодействия, а не защита от целевого автоматизированного обхода.
- Проверяются новые участники-люди; боты и администраторы пропускаются. Старые заявки и полная история участников не импортируются из Telegram.
- Для ограничения сообщений нужна супергруппа. В режиме проверки после входа возможен короткий промежуток между вступлением и установкой ограничения.
- Вызовы Bot API и операции базы не образуют общую транзакцию. Есть дедупликация и восстановление после ошибок, но строгая exactly-once доставка внешних действий не гарантируется.
- Журнал, ожидания и ключи дедупликации не очищаются автоматически. Для крупного сервиса потребуется политика хранения.

## Обновление и диагностика

После получения изменений из своей копии репозитория:

```sh
git pull --ff-only
npm ci
npm run deploy
```

Если менялись команды или настройки профиля, повторите `npm run setup:bot`.

| Команда | Назначение |
| --- | --- |
| `npm run status` | сравнить локальные файлы с последним облачным снимком |
| `npx tgcloud fetch` / `npx tgcloud diff` | обновить облачный снимок и посмотреть различия |
| `npm run check:cloud` | проверить модули, авторизацию и операции реальной базы без сообщений пользователям |
| `npx tgcloud webhook` | проверить webhook и типы событий |
| `npx tgcloud webhook sync` | восстановить webhook проекта |

Обычный `npx tgcloud push` не собирает фронтенд: после изменения интерфейса используйте `npm run deploy` или сначала `npm run build`.

**В браузере только «открыть в telegram»?** Это ожидаемо: реальные данные доступны при запуске из Telegram с подписанными init data.

**Чат не виден или не работает?** Подключите его из нужного аккаунта, проверьте права пользователя и бота, затем включите нужный режим. При переносе на другого бота права администратора нужно выдать ему отдельно.

## Разработка

```sh
npm ci
npm run dev
npm test
npx playwright install chromium
npm run test:ui
npm run build
```

`npm test` использует настоящую SQLite и имитацию Bot API. Браузерные тесты подменяют Telegram bridge только внутри тестов. Локальным тестам не нужны токены; нативное поведение клиента проверяйте на отдельном тестовом боте.

GitHub Actions запускает серверные тесты, сборку и браузерные сценарии на push и pull request. Автоматической публикации в Telegram из CI нет.

| Путь | Содержимое |
| --- | --- |
| `tgcloud/schema.js` | таблицы и индексы |
| `tgcloud/handlers/` | обработчики событий Telegram |
| `tgcloud/endpoints/` | серверные методы Mini App |
| `tgcloud/lib/` | капча, доступ, настройки и меню бота |
| `web/` | интерфейс Mini App и Telegram bridge |
| `tgcloud.jsonc` | размещение собранного `dist/` на Serverless |
| `tests/` | серверные и браузерные тесты |
| `scripts/cloud-check.mjs` | проверка облака и настройка профиля |

Подробнее: [устройство Mini App](docs/miniapp.md), [справочник SDK](docs/tgcloud-sdk.md), [участие в разработке](CONTRIBUTING.md).
